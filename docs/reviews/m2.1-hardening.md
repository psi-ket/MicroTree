## Part 1 — Initial inspection report (2026-11-02)

Every issue was checked against the code as it stood after M2. References are
`file:line` in that version.

### Issue A — Agent environment credential isolation (P0): **confirmed**

- `packages/agent-adapters/src/discovery.ts:100` forwards every variable
  starting with `ANTHROPIC_`, `CLAUDE_`, `OPENAI_` or `CODEX_` to **every**
  agent (built-in and custom). `OPENAI_API_KEY` therefore reaches Claude Code,
  `ANTHROPIC_API_KEY` reaches Codex, and both reach custom agents.
- `apps/runtime/src/services/ai/agent-service.ts:85,226`: one environment is
  built for all agents. There is no per-agent policy and no way to configure
  one.
- Agent stderr is published to the browser as activity
  (`agent-service.ts`, `case 'log'`), and agent errors are stored on the
  message. Nothing is redacted, so a forwarded secret printed by an agent
  would reach the UI.
- Existing test: `agents.test.ts:91` asserts the current, unsafe behaviour
  (`ANTHROPIC_API_KEY` is forwarded).

**Fix.** A single environment-policy module in `agent-adapters`
(`environment.ts`):
- a small base allowlist (system paths, home, locale, proxy);
- per-agent defaults (Claude Code: `CLAUDE_CONFIG_DIR`; Codex: `CODEX_HOME`;
  custom: nothing);
- explicit additions by exact name only, from the runtime's `agents.json`;
- name and value validation, plus a denylist that cannot be overridden
  (`RS_*` and loader-injection variables such as `NODE_OPTIONS` and
  `LD_PRELOAD`);
- sensitive names (`*KEY*`, `*TOKEN*`, `*SECRET*`, …) are forwarded only
  when allowed by exact name;
- the policy returns the forwarded secret values so the agent service can
  redact them from activity, errors and stored text.

**Tests to add:** per-agent exclusion (OpenAI → Claude Code, Anthropic →
Codex, both → custom), base variables forwarded, explicit allow, denylist
cannot be bypassed through `agents.json`, and redaction of secret values in
activity events and stored messages (fake CLI printing its environment).

### Issue B — Staging directory containment (P0): **confirmed, and broader than reported**

- `packages/agent-adapters/src/staging.ts:65-66`: `!rel.startsWith('..')`
  treats a staging directory at `<project>/..staging` as *outside* the
  project. This fails open.
- `packages/document-engine/src/node/path-guard.ts:9` (`isInside`, used by
  `PathGuard` for every project file operation) has the same pattern. There
  it fails *closed*: a legitimate file named `..notes.tex` is rejected as
  outside. That is not a security hole, but it is wrong.
- `packages/agent-adapters/src/shared.ts:9` (`relativeTo`) has the same
  pattern (display only).
- Staging is only checked lexically. Symlinks and junctions in the parents of
  the staging directory are not resolved, and the session id is not
  validated as a single path segment.

**Fix.** A central containment module in `document-engine/node`
(`containment.ts`):
- `isWithin` is segment-aware, works for both the `win32` and `posix` path
  APIs, and treats mixed separators correctly on Windows;
- `resolveWithin` checks the realpath of the nearest existing ancestor,
  which also resolves junctions;
- `assertDisjoint` checks that two trees do not overlap, using realpaths.

`PathGuard`, `StagingWorkspace` and `relativeTo` use it. Staging is built
from a runtime-owned root plus a validated session id, rejects any overlap
with the project, and skips links found while walking.

**Tests to add:** child, parent, sibling, `..staging`, `...data`, absolute
outside path, symlink/junction escaping and staying inside, `win32` paths,
mixed separators, and a junction inside staging surviving disposal.

### Issue C — Incomplete responses generating proposals (P0): **confirmed, and broader than reported**

- `apps/runtime/src/services/ai/assistant-service.ts:247-257`: `max-tokens`
  only sets a warning and keeps `status = 'complete'`, so `proposalsFromText`
  runs on a truncated answer.
- The same block treats `stopReason = 'other'` as `complete`. That includes
  an OpenAI or Gemini stream that ends without any finish reason, an
  Anthropic `pause_turn` or `tool_use`, and an Ollama stream without
  `done_reason`. Unexpected terminations are therefore treated as finished
  and can produce proposals.
- `StopReason` (`ai-core/src/types.ts:28`) loses the provider's raw reason.
- Agent turns are already gated on `status === 'completed'` (staging diffs
  only on completion). That stays.
- Existing test: `ai.test.ts` "flags refusals and truncated answers" checks
  the warning text, but does not check that no proposal is created.

**Fix.**
- In `ai-core`, `CompletionState` = `completed | truncated | cancelled |
  failed | incomplete` and a single `completionState()` mapping.
- Adapters report their raw finish reason alongside the normalised one.
- Message statuses gain `truncated` and `incomplete`. These are stored in
  the existing text column, so no constraint change is needed, and they are
  shown in the UI.
- Only `completed` turns are parsed for edit blocks. Other turns keep their
  text and get an explanation.
- A new `finish_reason` column records the raw provider reason (migration).

**Tests to add:** each case listed in the assignment, run against mock
OpenAI and Anthropic HTTP servers through the real adapters.

### Issue D — Model capabilities (P1): **confirmed**

- `packages/ai-core/src/catalog.ts:15-22` declares `toolUse: true` and
  `vision: true` for Anthropic, OpenAI and Gemini, but
  `ChatTurn.content` (`types.ts:16`) is a plain string and no adapter
  serialises images or tools.
- `structuredOutput` is accurate: `generateStructured` exists for Anthropic,
  OpenAI, Gemini and Ollama.

**Fix.**
- Capabilities are derived from what each adapter implements.
- `toolUse` and `reasoning` are `false` everywhere.
- `vision` is `true` only where the adapter serialises images (Anthropic,
  OpenAI, Gemini).
- `ChatTurn.content` accepts `string | MessageContent[]`, so text-only
  callers keep working.
- Image MIME types (checked against magic bytes), size and count are
  validated centrally in `ai-core`, with an `unsupported-modality` error.
- Each adapter has its own serialiser.

**Tests to add:** capability table, image serialisation per provider,
rejection on non-vision adapters, MIME/size/magic-byte validation, text-only
compatibility.

### Issue E — LaTeX compilation security (P0): **confirmed, with additional findings**

Verified on this machine (TeX Live 2024, Windows) with throwaway projects:

| Finding | Evidence |
| --- | --- |
| `docs/security.md` T8 says `openin_any=a` is set; `TEX_SECURITY_ENV` (`latex-engine/src/process.ts:189`) does not set it. TeX Live's default is `a`. | `kpsewhich -var-value=openin_any` → `a` |
| A document can `\input` an absolute path or `../file` outside the project and typeset it into its PDF. | pdfLaTeX exit 0 with `\input{C:/…/outside-secret.tex}` |
| `openin_any=p` blocks those reads. pdfLaTeX (BibTeX, biber, `\includegraphics`, `\input` of project files) and XeLaTeX (fontspec with a system font) still work. | probe: all pass with `p` |
| `openin_any=p` breaks **LuaLaTeX** entirely (`article.cls` not found: LuaTeX opens kpathsea results by absolute path). | probe: exit 12 |
| In LuaLaTeX, Lua `io.open` can read any absolute path. Writes outside are refused (`openout_any=p`) and `os.execute`/`io.popen` do nothing (`shell_escape=f`). | probe |
| TeX follows symlinks and junctions, and `openin_any`/`openout_any` check names, not targets. A link inside the project, including in `.rs-build`, could redirect reads or writes outside it. | by construction; checked in tests |
| `TEXMFOUTPUT` from a `texmf.cnf` would re-allow absolute writes under it. | not set in the environment |
| The full `.log`/`.blg` is read into memory regardless of size. | `latexmk.ts` `readIfExists` |
| MiKTeX ignores kpathsea environment variables; its own defaults apply. | not testable here (no MiKTeX) |

Existing tests cover shell escape, `latexmkrc`, a relative write outside the
project, timeout and cancellation. They do not cover reads outside the
project, absolute-path writes, links, environment isolation, process-tree
termination or log-size limits.

**Fix.**
- `openin_any=p` for pdfLaTeX and XeLaTeX. LuaLaTeX keeps `a`, documented.
- `TEXMFOUTPUT` forced empty.
- Compilation is refused when the project contains a link that resolves
  outside it.
- Log reads are capped.
- The docs are corrected and recommend an OS-level sandbox.

### Issue F — External file change reconciliation (P1): **confirmed (not implemented)**

- The runtime publishes `files.changed` only for its own writes
  (`project-service.ts:357`). Nothing watches the disk, as the README says.
- The web reloads clean buffers on `files.changed` but skips dirty ones
  (`apps/web/src/lib/live.ts`). A dirty buffer only learns about a conflict
  when a save is refused with 409.

**Fix.**
- A runtime `FileWatchService`: `fs.watch` with `recursive`, active while a
  client subscribes over the WebSocket.
- It is debounced and hash-based, ignoring the runtime's own writes, and
  classifies added, modified and deleted files, plus renames when the content
  matches.
- It publishes `files.changed` with `source: 'external'` and per-path change
  details.
- Web: clean buffers reload. A dirty buffer gets an immediate conflict bar
  with **Compare**, **Keep mine** and **Reload from disk**. Deleted and
  renamed files are handled. When the window regains focus, open buffers are
  checked again, as a fallback when watching is unavailable.

### Issue G — Agent staging cleanup (P1): **confirmed (only deletion with the conversation)**

- `agent-service.ts:277` (`discard`) removes a copy only when its
  conversation is deleted.
- Copies of finished, idle or orphaned sessions stay forever, with no size
  limit across sessions.

**Fix.**
- New `ai_staging_workspaces` table (migration `0001`): conversation,
  project, created, last activity, size, state.
- A staging lifecycle service: sweeps at start-up, every hour and after each
  run.
- It removes expired idle copies, orphans (no record, conversation or
  project gone) and least-recently-used copies above a total size limit.
- It never removes an active session, deletes only direct children of the
  runtime-owned staging root (containment-checked, links unlinked rather than
  followed), and audits every removal.

## Part 2 — Engineering report (2026-11-02)

All seven issues are fixed. Every result below comes from commands run on
this machine (Windows 11 Pro, Node 24.3.0, pnpm 9, TeX Live 2024). No real
API keys were used: model adapters are tested against a local mock server,
and agents against fake CLIs.

The project folder is not a git repository, so the changes could not be split
into commits. The sections below follow the order of the reviewable commits
they would have been (A → B → C → D → E → G → F).

### Fixes

**A — Agent credential isolation.**
- New `packages/agent-adapters/src/environment.ts` with
  `buildAgentEnvironment(agentId, source, policy)`.
- Base allowlist: system, home, app-data, temp, locale (`LC_*`, `XDG_*`),
  proxy and certificate variables. Per-agent defaults are `CLAUDE_CONFIG_DIR`
  for Claude Code and `CODEX_HOME` for Codex; there are none for custom
  agents.
- Provider keys and credential-like names (`KEY`, `TOKEN`, `SECRET`,
  `PASSW`, `CREDENTIAL`, `AUTH`, `COOKIE`, `SESSION`, `PRIVATE`) are passed
  only when the operator lists them for that agent in `agents.json`
  (`environment.<agent>.allow`, or `environment.allow` on a custom agent).
- `RS_*`, `LD_*`, `DYLD_*` and loader hooks (`NODE_OPTIONS`, `PYTHONPATH`,
  `PERL5OPT`, `BASH_ENV`, …) are denied outright. An `agents.json` that
  allows or sets one is rejected as a whole, and `set` cannot introduce a
  credential name.
- The forwarded credential values are returned as `secrets`. `AgentService`
  passes them through `createStreamRedactor` (`ai-core`), which also catches
  values split across chunks, and through `redactValues` for activity,
  errors, run records and audit details.

**B — Staging containment.**
- New `packages/document-engine/src/node/containment.ts` (`isWithin`,
  `isStrictlyWithin`, `areDisjoint`, `resolveWithin`, `assertDisjoint`,
  `realpathOfNearestExisting`). It compares path segments rather than string
  prefixes, so `..staging` and `...data` count as names inside a folder and
  only a real `..` segment leaves it. It handles drive letters
  case-insensitively on Windows, UNC paths and mixed separators, and re-checks
  with real paths. If a path cannot be resolved, it fails closed.
- `StagingWorkspace` asserts that the staging root is disjoint from the
  project and from `RS_WORKSPACE_ROOT` (lexically and by real path) before
  anything is created. It never follows links while copying and removes
  only strictly inside its root, unlinking links instead of following them.
- `PathGuard.isInside`, the adapters' `relativeTo` and the runtime test now
  use the same utility.

**C — Incomplete answers.**
- Adapters emit `done { stopReason, rawReason }`.
- Anthropic `model_context_window_exceeded` now maps to `max-tokens`; before,
  it was treated as a normal end.
- New `completionState()` and `CompletionState` in `ai-core`.
- `AssistantService.runModel` calls `proposalsFromText` only for `completed`
  answers. Every other state keeps its text, records its edit blocks in
  `editIssues` with the reason they were not offered, gets status
  `truncated`, `incomplete`, `cancelled` or `error` with an explanation,
  stores the raw `finishReason`, and is excluded from history.
- `edit-protocol.ts` now rejects unclosed blocks, nested blocks, duplicated
  sections and unknown targets.
- Web: `Message.tsx` shows the "Drafting an edit…" spinner only while
  streaming. An unfinished answer offers its raw text on request.

**D — Capabilities and multimodal contract.**
- `ModelCapabilities` gains `reasoning`, `maxContextTokens` and
  `maxOutputTokens`. The catalog reports `toolUse: false` and
  `reasoning: false` for all kinds, and `vision` only for Anthropic, OpenAI
  and Gemini.
- New `packages/ai-core/src/content.ts`: `MessageContent`, `IMAGE_LIMITS`,
  `sniffImageType`, `validateRequestContent`.
- New error code `unsupported-modality`.
- Each adapter serialises images itself. `ChatTurn.content` stays assignable
  from a plain string, so no caller changed.

**E — LaTeX.**
- `TEX_OPENIN` sets `openin_any=p` for pdfLaTeX and XeLaTeX and `a` for
  LuaLaTeX. `TEXMFOUTPUT` is forced empty.
- `findEscapingLinks` scans the project and `.rs-build` (up to 50 000
  entries), and `compileProject` refuses to compile with `VALIDATION_FAILED`
  when links point outside.
- `.log` and `.blg` reads are capped at 8 MB, with a warning diagnostic.
- Docs corrected (`security.md` T8 previously claimed `openin_any=a` was
  set, and it was not set at all).

**F — External file changes.**
- New `apps/runtime/src/services/file-watch-service.ts`, used through the
  WebSocket messages `project.watch` and `project.unwatch`.
- `files.changed` gains `source` and `changes`.
- Web:
  - `lib/live.ts` adds `syncChangedFiles`.
  - The editor store tracks `diskState`.
  - New `CompareDialog.tsx`.
  - The conflict bar and status bar show external changes and deletions.
  - The app watches the open project and re-checks open files on focus.

**G — Staging lifecycle.**
- New table `ai_staging_workspaces` and `StagingRepository`.
- New `apps/runtime/src/services/ai/staging-lifecycle.ts`.
- New setting `RS_AGENT_STAGING_MAX_BYTES`.

**Deviation from the Part 1 plan for G.** Part 1 planned to expire idle copies
and evict the least recently used ones above a size limit. The implementation
removes each copy as soon as its run ends, because every run rebuilds the copy
from the project anyway (session resume needs only the path). This makes
expiry and eviction unnecessary. The size budget therefore *refuses* a new
copy ("too large to copy") instead of evicting old ones, since only copies in
use count against it. The startup and hourly sweeps remove crash leftovers,
failed removals and directories with no record.

### Migration

`packages/ai-storage/migrations/0001_staging_and_finish_reason.sql` does two
things:
- Adds the nullable column `ai_messages.finish_reason`.
- Creates `ai_staging_workspaces` (session id primary key, project id, agent
  id, state, bytes, files, created and last-active timestamps, with an index
  on `last_active_at`).

The migration only adds things, so existing rows keep working (their
`finish_reason` is null). The runtime applies it at start-up, as it does all
AI migrations. A staging directory that predates the table has no record, so
the first startup sweep treats it as an orphan and removes it.

### Remaining limitations and unresolved risks

- **LuaLaTeX can read any file the user can.** It cannot start under
  `openin_any=p`, and Lua's `io.open` ignores the setting anyway. Writes stay
  restricted and commands cannot run. Use pdfLaTeX/XeLaTeX or an OS sandbox
  for untrusted projects.
- **MiKTeX** ignores the kpathsea environment settings. This is untested,
  since only TeX Live is installed here.
- **Hard links** into the project cannot be detected. The link check is also
  point-in-time, so a link created during a compile is not caught. Both
  require write access to the project folder.
- **No OS sandbox** for TeX or agents. This is restriction, not isolation. An
  agent's reads outside its copy are limited only by the agent's own sandbox
  (Claude Code `--tools`, Codex `--sandbox`).
- **Redaction** removes exact values only. Encoded or fragmented output from
  an agent that was given a key is not caught.
- **External changes:**
  - They are detected only while a client has the project open, with Node's
    `fs.watch`. Network drives may not deliver events, and the focus-time
    re-check is the fallback.
  - The snapshot stops at 20 000 entries or a depth of 24.
  - Files over 1 MB are compared by size and modification time.
  - A rename combined with an edit appears as a delete plus an add.
- **Vision:** `vision: true` means the adapter sends images. A specific model
  may still refuse them. There is no UI for attaching images yet (M4).
- **Limits:** `maxContextTokens` and `maxOutputTokens` are null at the
  provider level, because they depend on the model.
- **Not tested against hosted APIs.** Real-key tests against hosted APIs are
  still not part of the suite, by design.
