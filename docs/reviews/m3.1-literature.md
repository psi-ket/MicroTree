# M3.1 — Scholarly literature search engine

This file has two parts. Part 1 is the assessment and plan, written before any
code was changed. Part 2 is the engineering report, added at the end.

## Part 1 — Assessment and plan (2026-11-02)

### 1. Repository architecture assessment

- **Runtime boundary (ADR 0001).** Every network call, secret and file access
  lives in `apps/runtime` (Fastify). The browser talks only to the runtime's
  authenticated `/api/v1` scope (session bearer token, Host and Origin checks).
  The production CSP limits `connect-src` to loopback, so provider APIs
  *cannot* be called from the web app even by mistake. M3.1 must keep that
  shape: provider calls in the runtime, the web app consumes runtime routes.
- **Packages.** Domain logic sits in "just-in-time" TypeScript packages
  (ADR 0004): `shared-types` (plain interfaces and enums, no runtime deps),
  `api-contracts` (Zod schemas for every route and the typed
  `createRuntimeClient`), `database` (Drizzle + SQLite, generated SQL
  migrations, repositories), `ai-storage` (AI tables plus the `SecretStore`:
  OS keyring, file or memory), adapter packages that keep provider-specific
  code isolated (`model-adapters`, `agent-adapters`). The literature engine
  fits the adapter pattern: a framework-free package with isolated provider
  modules and an injectable `fetch`.
- **Routes.** Routes parse input with contract schemas (`parse()` →
  `VALIDATION_FAILED`), call a service, and errors are `StudioError`s mapped to
  HTTP by one error handler. Upstream failures already have codes
  (`PROVIDER_ERROR` 502, `RATE_LIMITED` 429, `TIMEOUT` 504, `NOT_CONFIGURED`).
- **Settings.** `SettingsService` stores validated key/value JSON in the
  `settings` table (`scope`, `key`). Secrets never go there; API keys go to
  the `SecretStore` (`provider:<id>` for model services), and the browser
  only ever learns whether a key is set.
- **Web.** React + TanStack Query + Zustand, hash routing in `App.tsx`
  (`#/p/<id>` = workspace, otherwise project list), the `@research-studio/ui`
  component set (Button, Input, Select, Switch, Dialog, Tooltip, Badge,
  resizable panels, theme tokens with light/dark), fonts STIX Two (display),
  Atkinson Hyperlegible Next/Mono. `apps/web` already has jsdom and Testing
  Library available for component tests.
- **Tests.** Vitest per package; the runtime tests build the real app on
  random ports; model adapters are tested against a local mock HTTP server;
  Playwright drives the real runtime and web dev server with mock services.
- **Evidence types.** `shared-types/src/evidence.ts` (future verification)
  refers to cited works by "DOI, arXiv id, or URL"; the new work model must
  provide exactly those identifiers so M3.2/M4 can link to it.

Gaps relevant to M3.1: nothing in the repository talks to scholarly services;
the runtime client has no `AbortSignal` support (needed for search
cancellation); there is no route for anything outside a project except
settings.

### 2. Provider integration plan (verified 2026-11-02)

Verified against each provider's official documentation and with one live
request per provider from this machine (no keys used):

| Provider | Endpoints used | Auth | Limits (as documented / observed) | Paging |
| --- | --- | --- | --- | --- |
| OpenAlex (`api.openalex.org`) | `/works` (`search`, `filter=title.search:`, `title_and_abstract.search:`, `raw_author_name.search:`, `publication_year:A-B`, `is_oa:true`, `type:`), `/works/{id}` (OpenAlex ID or `doi:`), `/authors/{id}`, `filter=cites:` / `cited_by:` | Optional `api_key` query parameter. Keyless requests work but share one free budget per IP (response `meta.notice`). | Usage-based: search $0.001, list/filter $0.0001, single entity free; $0.10/day without a key, $1/day with a free key; `X-RateLimit-*` headers (`Remaining-USD`, `Reset`) | `page`/`per_page` (≤100, ≤10 000 results); `cursor` for deep paging |
| Semantic Scholar (`api.semanticscholar.org/graph/v1`) | `/paper/search` (relevance, `year`, `publicationTypes`, `openAccessPdf`, `venue`, `fieldsOfStudy`), `/paper/{id}` (`DOI:`, `ARXIV:`, sha), `/paper/{id}/references`, `/citations`, `/author/{id}`, `/author/{id}/papers` | Optional `x-api-key` header | Keyless: shared pool, frequent 429s (observed twice today); with a key 1 request/s | `offset`/`limit` (limit ≤100, ≤1 000 results) |
| arXiv (`export.arxiv.org/api/query`) | `search_query` with `ti:`, `au:`, `abs:`, `all:`, `cat:`, `submittedDate:[… TO …]`; `id_list` for identifiers (versions supported) | None | Terms of use: at most one request every 3 s, one connection at a time, across all machines; cache results (feeds update daily) | `start`/`max_results` (≤2 000 per call, ≤30 000 total) |
| Crossref (`api.crossref.org`) | `/works` (`query.bibliographic`, `query.author`, `filter=from-pub-date,until-pub-date,type`, `sort`), `/works/{doi}` | None. `mailto` moves requests to the polite pool. | Since 2025-12-01: public pool 1 list request/s and 5 single-record/s, concurrency 1; polite pool 3 list/s and 10 single/s, concurrency 3; advertised in `x-rate-limit-*` headers | `rows` (≤1 000) + `offset`; `cursor` for deep paging |

Design:
- One shared HTTP layer (`http.ts`): per-provider request queue (minimum
  interval and concurrency from the table above), per-request timeout,
  `AbortSignal` propagation, retries only for 429/5xx/network errors with
  exponential backoff and `Retry-After`, at most 2 retries, response size cap,
  observations of rate-limit headers, and URL redaction (`api_key`, `mailto`)
  before anything is logged or stored.
- One module per provider (`client.ts` HTTP calls, `schemas.ts` Zod schemas
  for the parts of the response we read, `mapper.ts` to a source record).
  Provider code never leaks into search, dedup or ranking.
- No contact e-mail is sent by default. `RS_LITERATURE_MAILTO` opts into
  Crossref's polite pool and OpenAlex's contact parameter.
- Keys (OpenAlex, Semantic Scholar) are optional, stored in the runtime's
  `SecretStore` (`literature:<provider>`), or read from `OPENALEX_API_KEY` /
  `SEMANTIC_SCHOLAR_API_KEY`. arXiv and Crossref have no keys.
- arXiv Atom is parsed by a small strict XML reader written for this purpose
  (no DTDs or entity definitions, so no entity-expansion attacks) instead of
  adding `fast-xml-parser` and its six transitive packages.

### 3. Database model proposal

Added to `packages/database` (core tables, migration `0001_literature`):

- `literature_cache` — `key` (provider + request), `provider`, `kind`
  (`record` | `search`), `value` (JSON), `retrieved_at`, `expires_at`; index
  on `expires_at`. Records live 7 days, search pages 1 hour (arXiv: 24 h, as
  its documentation recommends). Expired rows are swept at start-up and
  hourly; a key change clears that provider's rows; the user can clear it.
- `literature_search_history` — `id`, `query`, `request` (JSON),
  `result_count`, `provider_status` (JSON), `created_at`; capped at 200 rows;
  can be turned off and cleared.
- `literature_provider_state` — `provider` (PK), `enabled`,
  `last_success_at`, `last_error_at`, `last_error`, `last_status`,
  `rate_limit` (JSON from headers), `updated_at`.
- Preferences (default providers, sort, page size, history on/off, search as
  you type) in the existing `settings` table under scope `literature`.

No PDFs, no personal library. The canonical work model (below) is designed
so that M3.2's library can store `ScholarlyWork` rows keyed by `id` with
their `sourceRecords`.

### 4. Data model and API contract proposal

`shared-types/src/literature.ts` (interfaces, shared by engine, contracts and
web):

- `ScholarlySourceRecord` — one provider's view of one work: `provider`,
  `providerId`, `recordUrl`, `retrievedAt`, normalised fields (title,
  abstract, authors, dates, venue, publisher, type and raw type, identifiers,
  URLs, open access, citation counts, bibliographic details, categories) and
  `extra` (provider-specific values that do not map to canonical fields).
- `ScholarlyWork` — the suggested shape, plus `dates` (published, online,
  print, submitted, updated; kept separate), `bibliographic` (volume, issue,
  pages, ISSN), `categories`, `citation.observations` (count per provider,
  with retrieval time) and `citation.citedBySource`, `conflicts` (field,
  values per provider, chosen provider), `sourceRecords`.
- `ScholarlyAuthor` — name, given/family, ORCID, affiliations, provider
  author IDs, position.
- Canonical IDs: `doi:<doi>` > `arxiv:<id>` > `openalex:W…` >
  `semantic-scholar:<id>`, resolvable later by `GET /works/:id`.

Routes (authenticated `/api/v1`, Zod-validated, in
`api-contracts/src/literature.ts`):

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/literature/providers` | Status, auth requirements, key presence (never the key), limits, last success/error |
| PUT | `/literature/providers/:provider` | Enable/disable, set or remove the API key |
| POST | `/literature/providers/:provider/check` | One cheap live request (connection test) |
| GET | `/literature/search` | Unified search: `q`, `mode`, `providers`, filters, `sort`, `limit`, `cursor` |
| GET | `/literature/works/:id` | One work, resolved through every provider that knows it |
| GET | `/literature/works/:id/references`, `/citations` | Reference and cited-by lists (OpenAlex or Semantic Scholar) |
| GET | `/literature/resolve/doi/*` | DOI resolution (DOIs contain `/`) |
| GET | `/literature/resolve/arxiv/*` | arXiv resolution (old-style IDs contain `/`) |
| GET | `/literature/authors/:id` | Author profile (`openalex:A…` or `semantic-scholar:…`) and recent works |
| GET/DELETE | `/literature/history` | Search history |
| GET/PUT | `/literature/preferences` | Search preferences |
| DELETE | `/literature/cache` | Clear cached metadata |

Search response: `works` (ranked), `total` (largest provider total, marked as
an estimate), `pagination { hasMore, nextCursor }`, `providerStatus[]`
(`success` | `partial` | `failed` | `rate_limited` | `skipped`, count, error,
duration), `query` (how the query was interpreted). Cursors refer to
server-side search state (provider positions and works already returned, so
later pages do not repeat earlier ones) that expires after 30 minutes.
Aborting the HTTP request aborts the provider requests.

### 5. Frontend integration plan

- New route `#/literature` (outside any project), reachable from the project
  list header and the workspace top bar (which saves first, like "All
  projects"). The editor is not changed.
- Three resizable panes built from the existing UI kit: filters and history
  (left), results (centre), details (right). Below 1024 px the panes stack and
  details open in a dialog.
- Search runs on Enter or the button; changing filters or sort re-runs it
  after a 600 ms debounce; "search as you type" is an opt-in preference
  because every keystroke costs provider quota (OpenAlex charges per search,
  arXiv allows one request per 3 s). Each search aborts the previous one, and
  a Stop button cancels.
- States: skeletons while loading, empty, error, partial failure (per-provider
  chips with counts and errors), pagination ("Load more").
- Cards and details show provenance everywhere: source chips, citation counts
  with their provider, conflicts, provider records with retrieval times, links
  to the original pages. Copy citation, copy BibTeX, download `.bib`.
- "Literature sources" dialog (also from Settings): per provider availability,
  connection test, auth requirement, optional key (write-only), last success,
  last error, limits and remaining budget where reported.
- All provider-supplied URLs are checked to be `http(s)` before they become
  links; all provider text is rendered as text.

### 6. Testing strategy

- Fixtures: real responses recorded from the four APIs on 2026-11-02 (trimmed
  to a few results), each documented with its request URL and retrieval date
  in `test/fixtures/README.md`. Edge cases use synthetic records that are
  labelled as test data and use the `10.5555` test DOI prefix.
- Engine unit tests (no network; injected `fetch`): schemas, mappers, every
  identifier normaliser, dedup (all cases listed in the assignment), merge
  precedence and conflicts, ranking and sort modes, query parsing, cursors,
  rate limiting, retries, `Retry-After`, timeouts, cancellation, partial
  failures.
- Runtime tests: the real app with providers pointed at a local mock HTTP
  server serving the fixtures: authentication, validation, search, partial
  failure, rate limits, resolution, works, authors, keys never returned,
  history, preferences, cache.
- Web: Testing Library (jsdom) tests for the search form, cards, details and
  sources dialog, including keyboard use and accessible names; one Playwright
  spec against a mock provider server.
- Live smoke tests (`RS_LITERATURE_LIVE=1`), skipped by default, one real
  search and one resolution per provider.
- Full regression: `pnpm turbo run typecheck lint test build --force` and
  `pnpm test:e2e`.

### 2. What was built

- **`packages/literature-engine`** (new): one module per provider (client, Zod
  schemas of the fields read, mapper), a shared HTTP layer (pacing,
  timeouts, retries, cancellation, size cap, redaction, observations),
  normalisers, deduplication, merging with provenance and conflicts,
  deterministic ranking, server-side cursors, and a browser-safe `format/`
  entry (BibTeX, citation, safe URLs). Described in
  [`LITERATURE_ENGINE.md`](../LITERATURE_ENGINE.md).
- **`shared-types`, `api-contracts`, `database`**: literature types, Zod
  schemas pinned to them, `client.literature.*`, three tables and migration
  `0001_literature` with repositories.
- **Runtime**: `LiteratureService` and `routes-literature.ts`, config
  (`RS_LITERATURE`, `RS_LITERATURE_MAILTO`, `RS_LITERATURE_TIMEOUT_MS`, base
  URLs, environment keys), audit events. Routes in
  [`API_SPECIFICATION.md`](../API_SPECIFICATION.md).
- **Web**: `#/literature` (`features/literature/`), entry points in the
  project list and the workspace top bar, Sources dialog.
- **Test infrastructure**: `e2e/mock-literature-server.mjs`, which serves the
  recorded fixtures and can be told to rate-limit, fail or hang per provider,
  and reports abandoned connections; it backs the runtime tests and the
  Playwright spec.

### 4. Deviations from the Part 1 plan

| Plan | Built | Why |
| --- | --- | --- |
| `PUT /literature/providers/:provider` | `PATCH` | Partial update: either field can be sent alone |
| `POST …/check` | `POST …/test` | Matches the button label ("Test connection") |
| `GET /literature/search` with query parameters | `POST /literature/search` with a JSON body | Filters are nested and lists; a body is validated by one strict schema and has a 16 KiB limit |
| `GET/PUT /literature/preferences` | `GET/PATCH` | Partial update |
| — | `DELETE /literature/history/:entryId` | Removing one recent search from the UI |
| arXiv searches cached 24 h | 6 h | arXiv announces new papers daily; a 24 h cache could hide a day's new submissions |
| `enabled` and `last_status` in `literature_provider_state` | Provider switches in `settings` (scope `literature`); the table keeps only health (`last_error_kind` added) | Switches are preferences; health is observed data and is reset on key changes |
| "Search as you type" preference | Not built | Every keystroke would spend provider quota (OpenAlex bills per search; arXiv allows one request per 3 s); Enter or the button runs a search |
| Three resizable panes; below 1024 px stacked, details in a dialog | Fixed widths, three columns from 1180 px; narrower screens put filters in a drawer and show the details in place of the results (Back returns) | Kept the layout to fixed, tested breakpoints; resizing was not needed for the milestone's flows |
| Filters re-run the search after 600 ms | Checkboxes and selects apply at once; typed fields (years, author, venue, categories) apply on Enter or **Apply filters** | No search is sent for a half-typed value such as a three-digit year |
| Skeletons while loading | A spinner line with "Asking N sources… Press Esc to stop." | Says what is happening and how to stop it |

### 5. Findings outside the milestone

- **Colour contrast.** The shared `ink-faint` token measures 2.7–3.8:1
  against its backgrounds (WCAG AA needs 4.5:1 for text), and success/warning
  text on their soft fills is about 4.0:1 in the light theme. axe-core found
  this on the new page. The literature UI uses `ink-muted` and neutral tags
  instead; the global token was not changed because that would restyle the
  whole app. Recommended follow-up.
- **Line endings.** The repository mixes CRLF and LF files (it already did
  before this milestone). Some files edited here were written with CRLF by a
  script. There is no `.gitattributes` or `.editorconfig`; adding one and
  normalising once is recommended before the first commit.
- **Not a git repository.** Nothing is committed; the changes exist only in
  the working tree.
- **New dev dependencies** (web): `axe-core` 4.14.0 and
  `@testing-library/dom` 10.4.2.

### 7. Known limitations and follow-ups

- Semantic Scholar live verification (with a key).
- Relevance across providers is approximate; it uses only returned metadata.
- Category filters outside arXiv are approximated by field of study.
- Inserting a work into a project's `.bib` (with key collision handling) and
  a personal library belong to M3.2.
- The global contrast token and line-ending normalisation (§5).
